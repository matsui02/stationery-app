## 10. 技術スタック（手段としての技術）

### 10-1. 使用予定の技術

- フレームワーク：Rails
- DB：PostgreSQL
- デプロイ先：Render
- 使用予定ライブラリ：devise, CarrierWave, MiniMagic, Ransack, Noticed, Ancestry

---

### 10-2. 技術選定の理由

- なぜこの技術を使うのか
PostgreSQLに関してはRailsとの相性が良い為採用していて、deviseに関してはユーザー認証機能を簡単に実装することができ、CarrierWaveは画像アップロード機能をシンプルに実装できMiniMagickはCarrierWaveと組み合わせることができるため採用した。Ransackは複雑な検索条件を簡単に実装することができる為。通知機能にはNoticed、コメントの階層構造管理にはAncestryを採用した
- 今回チャレンジしたい点
通知機能とコメント機能の実装
- 不安な点
NoticedとAncestryは初めて扱う為、導入方法や実装の仕方に不安がある

---

### 10-3.キャッチアップ不足の懸念

キャッチアップ不足の段階では以下の懸念点があります。

1. **完成までのハードルが高い**
   使用する言語やフレームワークが異なるため、キャッチアップにかかる時間は個人差があるものの、一定の時間を要することが予想されます。
2. **Issueの見積もりが難しい**
   「どこまで理解していて、何が分からないのか」「調査にかかる時間」などが不明瞭な場合、開発期間内に完了することが難しくなってしまいます。

例えば、最近注目されているReactやNextについて。
Reactについては**本リリース後に組み込む方向で検討**するのが良いかと考えています。
その後、React単体のキャッチアップを行い、アプリに組み込む技術的な検証をした上で、組み込むかどうかを判断する形が理想かもしれません。
